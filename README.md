# 给家里的语音提醒 · 比赛原型

在 WSL Ubuntu 安装 [Tesseract 及其简体中文语言包](https://tesseract-ocr.github.io/tessdoc/Installation)。需要 Python 3 和 Pillow。首次安装依赖后，在仓库根目录运行原型：

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-chi-sim
python3 -m pip install Pillow
```

```bash
python3 prototype/app.py
```

打开 http://127.0.0.1:8791/ 。从首页选择「拍报告，看解读」或「拍用药单，设提醒」。首次使用可点击「扫描示例 · 虚构」，示例同样经过本地 OCR。用药确认后显示下一次提醒，到点显示大字提醒并尝试播放语音。浏览器阻止自动播放时，页面提示点「听听提醒内容」。同一 Wi-Fi 下用手机体验，可用服务所在机器的局域网地址绑定 `--host` 并用手机浏览器访问该地址；如果在 WSL 内运行，局域网访问还取决于 Windows 网络设置。

在「提醒」页打开「提醒设置」，可调整三餐时间、核对提醒并开启。音频可以在提醒页更换。三餐时间、已确认的提醒安排、提醒开启时间保存在当前浏览器。提醒按北京时间每天重复，浏览器页面须保持打开。页面挂起后回前台时只补显示最近 15 分钟内的到点提醒。同一个页面重复刷新不会重复触发已经处理的提醒。这个原型未实现锁屏、关闭页面后的系统通知。不要把它当作实际服药的唯一提醒。

示例语音为已有普通话演示。点「换成自己的音频」可在当前页面试听已准备好的授权录音或者合成音频。文件不上传，刷新后恢复示例。

## 队友接入

- 「体检」拍照后用本机 Tesseract OCR 读取表格，匹配现有 15 项常见指标。血红蛋白、白细胞和血小板也支持常见中英文并排和括号参考范围。完整的单行结果直接展示解读草稿。用户可展开原图核对并保存大字卡。读不清的项目提示重拍，体检流程无需手动录入。
- 「用药」优先拍清个人用药单或现行医嘱。识别到每天一次、餐次明确、单次用量明确时，弹出确认面板。明确间隔可计算钟点，只写餐前或餐后时由用户选提醒时间。确认后直接开启。模糊、冲突、复杂或按需安排提示重拍或核对原始材料。页面通过拍照识别药品信息，不设手填入口。队友可参考 [结构化结果格式](prototype/demo-result.json)。
- 两类卡片都可以导出 PNG。照片送到本机原型服务的 OCR 接口处理，不发到外部服务或落盘。自选音频只由浏览器读取。体检识别结果仅在本次页面打开期间可用。用药安排和提醒存在当前浏览器。虚构扫描示例建议在独立浏览器会话使用。
- 日常提醒优先播放千问生成的普通话语音，包含已核对的提醒钟点、药名、餐次、每次用量及照片上明确写出的饮食提示。没有可靠原文时不生成饮食禁忌。「提醒」页的「提醒声音」说明到点播报内容；「听听提醒内容」可提前试听下次提醒，未开启提醒时不显示声音区域。浏览器限制自动播报时可点播放。手动选择音频后可点「恢复自动播报」切回。千问临时不可用时尝试本机中文语音，虚构示例也有预存音频。手机后台通知尚未接入。
- OCR 和页面无需外部模型 API、数据库或登录服务。配置千问凭据后可启用可选的云语音。

队友联调格式采用 `{ "reminders": [...] }`。每条需提供 `name`、`source`（来源或经核对的原文）和 `confirmed`。可提供 `dose` 记录已核实的规格与用量。用药时段使用 `meal`（breakfast、lunch、dinner）与 `relation`（before、after、at，at 表示随餐）。如来源明确说“餐前/后 N 分钟”，使用整数 `minutes`。仅有“餐前/餐后”时应留空，页面请家属手动选择提醒钟点。用法、餐次或来源不完整的条目保留为待确认。后续接入该格式时仍须核对后再开启提醒。

比赛示例读出「每天午饭后一粒」。确认实际提醒钟点后，页面开启每日提醒。本轮已去掉「5 秒后试响」和「知道了」按钮，避免与正式用药流程混淆。到点状态保留在页面，刷新后显示下一次提醒。

演示顺序可用「体检 → 扫描示例」查看解释，再用「用药 → 扫描示例」验证用法识别与自底部弹出的提醒确认。两个示例都经过真实 OCR。

## 千问语音配置

服务端用 `qwen-audio-3.1-tts-next` 的 [音频生成接口](https://platform.qianwenai.com/docs/api-reference/audio-generation)。在运行服务的终端配置 `CARE_QWEN_TTS_KEY`。也识别已有的 `DASHSCOPE_API_KEY`。命令可用终端隐藏输入，避免把密钥写入文件或 shell 历史：

```bash
read -rsp '千问 API Key: ' CARE_QWEN_TTS_KEY
export CARE_QWEN_TTS_KEY
python3 prototype/app.py
```

浏览器只把已核对的提醒文稿送到本机服务，原照片与 OCR 全文不交给千问。服务端只在本机地址提供这个付费接口，本机服务和浏览器都会复用相同文稿的音频。支持浏览器缓存时，刷新后也可复用，同一浏览器最多保留 8 条，超过 7 天不再复用。修改时间、剂量或饮食文稿后会生成新音频。确认提醒后会提前准备，触发后会尝试准备下一条。共享到局域网前需要另行部署并加访问控制。

Harness Skill 版本见 [harness-skill 分支](https://github.com/yangeer/elder-health-assistant/tree/harness-skill)。
