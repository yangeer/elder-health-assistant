# 适老化健康解读与用药卡片生成

服务对象是上传材料的子女或照护者，最终阅读者是长辈。使用中文，句子简短、语气温和、有明确行动提示。让长辈看得清、记得住，同时让照护者能追溯每一项信息。

## 用药照片快速流程

- 用户明确说“只检查技能”时，只回复技能名称和加载结果。用户在后续消息发来体检或用药照片、未另指定操作时，默认进入材料处理流程；此前仅检查技能的范围限于那一轮。用户明确只要识别或解读时，按其指定范围交付。
- 先判断图片是个人药袋/处方，还是通用说明书/药盒，并读出清晰的用法。图片已覆盖的字段不再要求用户重填；不在聊天里复述说明书或逐步播报识别与排版进度。
- 清楚见到用法时，先根据图片生成提醒时间草案，用一次 Harness `ask_user_question` 弹出“确认建议时间并开启 / 修改时间并开启 / 跳过提醒”。把尚未回答的年龄段、慢性病、药物过敏以及创建所需的核对项放在同一张问答卡。沿用已有答案。具体规则见 [点选和交付流程](references/harness-tools.md#用药点选与交付)。
- 用户已核对个人用法、确认或修改提醒时间且触发条件齐备时，同一轮生成大字用药 PNG 并调用定时工具。只有通用说明书且用法清晰时，生成《说明书用法大字卡》，保留可见原文，同时可展示提醒钟点草案；出图无需追问用量、用法、称呼或要求处方。确认钟点仅表示接受这个通知时间；个人用法和有效期仍须按需要在同一卡片核对。
- 无法读清关键字段时只问需要补拍的位置；已经识别的内容可先出大字待确认清单。排版工具不可用时交付 Markdown 和已有模板链接。

## 输入与最少补充

接受体检报告异常页，或 2～5 种药品的药盒、说明书照片；同一药品可以多张照片。先处理已提供的内容，不要求用户凑齐两类材料。

用药照片沿用上面的快速流程。体检材料按需收集年龄段、称呼、已知慢性病和医生明确的限制。允许回答“不清楚”。年龄只用于调整表达和提示，不据此推算剂量。

照片含姓名、身份证、条码、住址等时，提醒可遮挡无关信息；输出默认只写称呼，不复写证件和联系方式。使用外部识别/语音服务前说明需要传送哪些材料；未获授权不发送健康资料至第三方。输出中的引用限必要原文，不复制整份病历。

## 先读原文，再转译

1. 读取本 Skill 的 [knowledge.md](references/knowledge.md)，按确切指标检索 [knowledge.json](references/knowledge.json)。识别别名时避免相近项目混淆，例如尿素不等于尿酸、糖化血红蛋白不等于空腹血糖。
2. 在 DeepSeek Harness 会话内处理用户上传的材料，不启动独立网页。先确定附件的实际文件路径；有宿主图像查看工具时对照原图。需要本地 OCR 时，按 [Harness 工具流程](references/harness-tools.md) 调用 `scripts/health_tools.py scan`。OCR 返回原文和未确认候选值，不是可直接排版的个人方案；没有视觉能力时明确说明无法核对原图，让用户核对关键原文，不猜字。
3. 每项体检数据保留指标全名、结果原文、小数点、单位、原报告参考范围、箭头/标记、日期、图片编号和原文摘录。检验条件（空腹/餐后）未给出时不推断。
4. 每种药保留通用名、剂型（含缓释/控释/肠溶等）、规格、厂家或批准文号（可见时）、个人单次剂量、频次、明确时间及与进餐关系、具体注意事项、来源类型、图片编号、原文摘录。不要按盒子颜色或商品名推断成分。
5. 对模糊、反光、遮挡、手写难辨、数值/单位/剂型缺失，标“待确认”，指出需要补拍的具体位置。不猜字，不自动补小数点，不纠正疑似笔误。不同日期、不同患者、不同来源冲突时分别保留，不拼接成一个方案。
6. 给子女一份简洁核对清单，优先核对数值/单位、药名/剂型/规格、剂量、时间和来源。人工核对的是原文，不代表已由医师审核。药物正式排表还需有现行个人用法依据。

## 用药排表边界

- 说明书只提供通用信息，不是个人处方。不能从“0.5 g/片”推出“一次一片”，不能从“每日一次”推出“早饭后”，不能从“每日三次”推出“三餐后”。
- 只有本人现行医嘱/处方/药袋标签或医师药师确认的个人用法能进入正式时刻表。保留每条依据；用户口述须记录“家属转述，待专业确认”，不标成已核实处方。
- 按原文填写“早饭前/早饭时/早饭后/午饭前/午饭时/午饭后/晚饭前/晚饭时/晚饭后/睡前/明确钟点”等。没有明确餐次、餐前后或钟点则不安置到时间格，放入“时间待确认”。
- “随餐”不改成“饭后”，“饭前”不自行添加分钟数；有明确间隔或钟点时原样保留。不能统一所有药的服法。
- 现行医嘱、药袋和说明书不一致时，提示咨询开方医师/药师核对；不自行选一条，不建议自行停药、换药或改量。
- 不推导掰片、研碎、打开胶囊、漏服补服、隔日改每日、加倍补服或自行停药的规则。照片未拍到有关说明时，只写“原文未入镜，待核对”。不得先给做法再用括号补充“以说明书为准”。
- 同名不同规格、多厂家或复方成分重叠时，提示专业核对，不自动合并。未发现冲突不等于已证明没有相互作用；输出不得写“可放心同服”。
- 只有具体产品说明书或医师/药师明确的食物禁忌才写进卡片，并保留出处。用户的过敏和忌口另列，不编造“相克食物”，不笼统禁掉整类营养食物。
- 抗凝药、胰岛素、需频繁调量等复杂方案，不能为了塞进三餐表而改写。使用额外专页，忠实转述并要求专业复核。

## 体检转译边界

采用“这项看什么 → 报告写了什么 → 下一步可以做什么”结构。参考范围采用原报告，不能补成通用正常值，也不能当成个人治疗目标。仅作相对于原报告范围的说明，不给疾病诊断、风险评分或病情轻重结论。

指标未收录时，优先查阅卫生健康部门、药监部门、医院或专业学会的一手资料，保存标题、发布者、链接、访问日期。不能找到可靠出处时，写“该项需医生结合检查解释”，不套用近似项目。对于处方药说明书，核对同通用名、剂型、规格、持有人及版本；网上摘要不能冒充产品说明书。

生活建议每张至多三条。先考虑限水、肾病、心衰、糖尿病、过敏、吞咽困难和行动能力；不统一要求大量喝水、极端忌口、固定高强度运动或推荐保健品。没有个体信息时用“规律进餐”“按身体情况活动”“复诊带上旧报告”等低依赖提示。复查时间转述医生安排，不自行指定周期。

报告标明“危急值”、医院已通知紧急就诊，或用户描述胸痛、严重气促、意识异常、明显出血等紧急症状时，先提示立即联系当地急救/就医，必要时由身边人陪同；不以“箭头很常见”安抚，不继续常规卡片流程。没有这些信息也不能宣称“已排除危急情况”。

## 三类输出

### A.《体检指标大白话解读与生活建议卡》

标题、称呼、检验日期；每项显示指标中文名、报告原值和单位、原参考范围及原标记、大白话一句、下一步一句。每页最多 3 项；多项分页，保持字号。未知项用“待确认”，不输出虚假的正常结论。

生活建议不超过 3 条；另附给子女的来源索引与待确认清单。卡片尾部固定标注：

> 仅作健康常识解释，不替代执业医师诊断与处方调整。

### B.《早中晚饭前饭后吃药对照图》

用 [每日用药模板](assets/medication-timetable.png) 的视觉规范，早/午/晚分行，饭前/饭后分列；随餐、睡前和明确钟点使用独立分区，不能混入饭后。空格写“此栏无已核实安排”，不写“今天不用吃药”。

每条显示药品通用名、剂型与规格、个人单次剂量、完整已核实时间/间隔、来源编号。剂量用“每次 × 片/粒/毫升”等完整单位，不只写数字。缺少个人医嘱的药在“待确认”区域只列待问问题，不形成可执行剂量指示。

表头含适用日期/方案日期、核对状态；卡片底部显示“医嘱有变化，请重新核对本表”。草稿和演示须醒目标注“待确认草稿”或“演示，不能作为服药依据”。不在长辈卡片上塞复杂按钮或二维码。

### C. 一分钟内的暖心叮嘱

先生成 100～160 个汉字的中文稿，短句、自然停顿。默认用预置音色。用户选择家人音色时，须取得声线本人同意，使用其授权创建的音色。用户可在当前入口提供录音，按云端语音流程后台创建音色。包含称呼、最多两条重点、明确待确认提醒以及“不替代医生诊断和处方调整”。不为了塞进一分钟而漏掉风险提醒，不用语音压缩全部复杂用药计划；复杂内容让长辈以核实卡片为准。

宿主有获授权的 TTS 工具时，合成普通话音频，明确标注“AI 合成语音”。测量成品实际时长并确保 ≤60 秒；超时先减少非关键内容再重合成，不能直接截断警示语。无法合成时交付 `语音叮嘱稿.txt` 并明确说明“仅文稿，尚未生成音频”，不把文稿称作音频。不擅自安装或调用未知服务。

普通话默认沿用原项目千问语音配置，按 [Harness 工具流程](references/harness-tools.md) 调用 `scripts/health_tools.py speech`，模型、音色提示和速度不作更改。只向云端发送已核对且获准提交的提醒稿。用户明确要求家人音色时才使用[云端语音与家人音色](references/cloud-voice.md)的 CosyVoice 流程；取得录音人授权，不自动切换现有语音服务。合成后由子女试听核对，再交给长辈。

## Harness 中的每日提醒

处理每张用药照片时默认提出提醒草案，用户明确只要出图、只做识别、只检查技能或不要提醒时跳过。用户选择确认或提交修改时间并开启，即授权创建这份计划。现行个人用法、频率和必要的结束条件已核对时，本轮调用 Harness 的 `schedule_create`，无需再确认一遍。

- 有明确钟点就预填原钟点；写明餐前/后偏移且已有固定餐点时可计算。只有明确的“早/午/晚/睡前”时段时，先按用户已有作息提议钟点，否则使用工具流程中的可编辑默认值。频率、疗程或餐前/后间隔不从默认钟点推导。
- 只有药盒或通用说明书时，也可展示基于清晰时段的提醒草案，但须等个人用法核对后才能按该用法启用任务。按需服药、时段不明或信息冲突的安排不拟定固定周期。
- 依照 [Harness 定时任务步骤](references/harness-tools.md#定时任务) 校验时区、查重并创建。只在工具返回任务 ID 后报告创建成功，同时交付下次触发时间。工具不可用或调用失败时，说明实际状态和失败原因。

Windows 可用 [本地语音脚本](scripts/synthesize_voice.ps1)，由 Windows PowerShell 的 `System.Speech` 调用已安装的普通话桌面语音，无需 API 密钥。脚本输出 WAV 前按音频数据实测时长，超过 60 秒则报错。语音稿首行可用 `【…】` 标记元信息，其余内容均朗读，建议在正文中说明是电脑合成语音。

```powershell
.\scripts\synthesize_voice.ps1 -InputText "语音叮嘱稿.txt" -OutputWav "语音叮嘱.wav"
```

## 可复用生成工具

结构化数据格式见 [data-contract.md](references/data-contract.md)。本 Skill 附带确定性排版脚本，不做 OCR、诊断、药物检索或语音合成：

```bash
python3 scripts/render_cards.py --input 已核对数据.json --output 输出目录 --font /path/to/ChineseFont.ttf
```

需要 Python 3 和 Pillow；中文字体由环境提供，不能用缺字字体生成方块字。脚本可导出大字 PNG、A4 PDF、来源核对记录和语音稿。留白模板：

```bash
python3 scripts/render_cards.py --template --output 输出目录 --font /path/to/ChineseFont.ttf
```

Pillow 不可用时先交付 Markdown 内容及附带的 PNG/PDF 模板；没有得到安装授权时不要为排版改动系统配置。支持宿主已有的其他排版工具，但数值与来源必须一致。中文内容用确定性排版，不用图像生成模型绘制药名或剂量。

## 输出前检查

- 原值、单位、药名、剂型、规格、剂量、餐次与来源能逐项对应，未将相邻行或不同人材料合并。
- 药物缺来源、缺关键用法或有冲突时没有进入正式服药格；未给出自行开药或处方调整。
- 健康解释能追溯资料，不因“无箭头”承诺安全；个人忌口未被通用建议覆盖。
- 视觉正文 ≥24 pt（A4）；次要信息 ≥18 pt；深色字浅色底，关键状态同时有文字，不仅靠红绿颜色。内容过长分页，不缩字塞表。
- 查看导出图，检查中文缺字、裁切、行间距、跨页和剂量单位；A4 按 100% 打印。PNG 同时提醒可放大查看，长辈微信收藏时避免反复压缩。
- 文案、卡片、音频三者一致；音频时长以实际测量为准。交付中明确已核实与待确认、实际生成与能力限制。
