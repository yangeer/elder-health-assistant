# DeepSeek Harness 工具流程

本 Skill 在 Harness 内执行，不需要 `prototype/app.py`。下列路径相对于 Skill 目录；从工作区根目录运行时加 `.dsh/skills/elder-health-cards/` 前缀。包含空格的路径须引用。输出放在工作区 `outputs/harness/本次任务/`，不同任务使用不同目录。

## 照片读取

```bash
python3 .dsh/skills/elder-health-cards/scripts/health_tools.py scan --kind report --image "用户附件路径.png" --output "outputs/harness/本次任务/ocr.json"
```

用药照片改为 `--kind medication`。使用本机 Tesseract，不上传照片。读取输出 JSON 中的 `raw_text` 和 `candidates`，对照原图及用户核对结果。候选提取只支持部分清晰格式，不能把空候选解释为正常或无用药。保留不完整原文并追问；不要修补 OCR 错字。返回的 `confirmed=false` 必须保留，不能把识别成功当作核对成功。

## 用药点选与交付

图片用法读得清楚时，第一条对用户可见的交互用 `ask_user_question` 点击卡。该工具不可用时给一组简短的编号选项，允许一条消息提交。问题只包含尚未回答的字段，一次发送：

- **年龄段**单选，提供“18–59 岁”“60–74 岁”“75 岁以上”“其他或不清楚”。年龄只影响表达和需要核对的事项。
- **慢性病**多选，提供“无已知”“有，可补充名称”“不清楚”；只在原文有相关提醒时加对应选项。“无已知”或“不清楚”不得和明确病史同时使用。
- **药物过敏**单选，“无已知”“有，可补充药名”“不清楚”。已知冲突或无法核对原文所需的关键信息时，保留待确认状态。
- **提醒草案**在题干列出原文时段、建议钟点和时区，允许“确认建议时间并开启”“修改时间并开启”“跳过提醒”。先用原文钟点，其次用已知作息及明确偏移；若原文只写“早/午/晚/睡前”且没有已知作息，可分别预填 08:00、12:00、20:00、22:00 作为可编辑的通知钟点。对“早晚各一次”显示“原文：早晚各一次；建议提醒：08:00、20:00”。这些钟点只是通知草案，不写入说明书原文，不能推导服药间隔或餐前后关系。仅写“每日两次”或只有“饭后”且餐次不明时，询问缺失的时段。
- **用法核对**只在个人用法仍待确认时加入同一张卡，已有核对结果直接沿用。频率和结束条件有缺口也在同一卡片收集。自定义答案应给出改后的钟点并说明是否开启；若选“修改”但没有提供钟点，只补问修改值。用户只要求出图时跳过提醒问题，默认称呼“长辈”。

用户提交后直接调用排版脚本；当已授权、个人用法和触发条件齐备时，再在同一轮调用定时任务。最终回复只给 PNG 链接、提醒结果和必要的缺失项；语音或 PDF 按需附送，不为排版和识别单独发进度消息。

## 核对与排版

读取 [data-contract.md](data-contract.md)，由 Agent 将原文整理为约定格式，未核实项为 `confirmed=false`。展示关键数值、单位、药名、剂型、个人用法和来源供用户核对；仅根据实际回复更新确认状态。不要把扫描结果直接传给排版脚本。

说明书用法清晰时，用 `source_type="leaflet"`、`source_id` 和 `source_quote` 保留原文，令 `confirmed=false`、`events=[]`、`dose=""`。将生成的《说明书用法大字卡》作为主附件，图上分开显示药品、原文和来源。只在用法不清楚时交付待确认清单；药名也不清楚时用 `render_cards.py --template` 交付留白模板。回复只给主附件和用户需要知道的提醒状态。

```bash
python3 .dsh/skills/elder-health-cards/scripts/render_cards.py --input "outputs/harness/本次任务/已核对数据.json" --output "outputs/harness/本次任务/卡片" --font "/mnt/c/Windows/Fonts/msyh.ttc"
```

字体路径是当前 WSL 环境示例，其他部署须选择实际存在的中文字体。PNG/PDF、来源记录和语音稿由脚本生成；在会话里给用户可打开的成果链接。宿主可查看图片时检查输出裁切和缺字。

## 普通话语音

沿用已有 `CARE_QWEN_TTS_KEY` 或 `DASHSCOPE_API_KEY` 环境变量。不要读取、打印或写入密钥。先明确外部语音服务会收到文稿，取得用户授权；无授权时仅交付文稿。

```bash
python3 .dsh/skills/elder-health-cards/scripts/health_tools.py speech --text "outputs/harness/本次任务/卡片/语音叮嘱稿.txt" --output "outputs/harness/本次任务/叮嘱.wav"
```

脚本复用原千问模型、提示和 0.9 语速，校验 WAV 且最长 60 秒。缺凭据或服务失败时保留文稿，明确未生成音频；不要自行改服务。音频与卡片逐项核对。

## 定时任务

1. 只为用户已授权且已核对的个人安排建任务。优先使用用户指定的时区，其次使用会话可用的用户时区；两者都未知时询问。排程使用当地钟点，保留原定频次和结束条件。仅写了一次或有限疗程时使用对应的一次或有限重复规则，不能改成无限重复。
2. 调用 `schedule_list` 检查是否已有同一安排的有效任务。已存在则回报原任务 ID；用户明确要求调整时才编辑已有任务，不能重复创建。每个不同钟点可单独建一条任务，使用 `this_session` 投递到当前对话，除非用户指定其他目标。
3. 以当前工具定义为准。本项目 Harness 的 `schedule_create` 使用 `title`、`prompt`、`rrule` 和 `target`。例如，已核对为北京时间每日 08:30 且用户授权的演示安排，`rrule` 用两行 `DTSTART;TZID=Asia/Shanghai:20261120T083000` 和 `RRULE:FREQ=DAILY`。实际使用对应日期和钟点；有截止日期时按工具定义表达。任务指令只发送已核对的提醒内容，不添加新的医疗判断。
4. 逐条回报任务 ID、时区、频率和工具返回的下次触发时间；部分失败时逐条标明，不重建已成功的任务。任务按时向目标会话投递，需运行 Harness，不承诺手机锁屏推送或自动播放。

## 依赖

Python 3、Pillow、Tesseract 和 chi_sim/eng 语言包，以及中文字体。Harness 需要模型配置和可执行 shell 的工具权限。使用当前会话的工具；Skill 文档不会自行注册新工具。
